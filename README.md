# Uni-DTHON 배터리 열폭주 단계 분류

센서 시계열과 열화상 이미지로 각 관측 시점의 열폭주 단계(1~6)를 예측한다. 최종 구성은 **입력 106개, LightGBM 1개, 실험별 누적 최댓값 보정**이고 Public Macro F1은 **0.8946**이다.

```
센서 CSV ──┬─> 원본 17개
           ├─> 시계열 파생 50개 ──┐
           └─> 규칙 신호 33개  ──┤
                                 ├─> LightGBM (입력 106개) ─> 가장 큰 확률의 단계 ─> 실험별 누적 최댓값 ─> final.csv
열화상 이미지 ─> 밝기 통계 6개 ──┘
```

## 1. 실행 방법

```bash
pip install -r requirements.txt

# 예측만 (저장된 가중치 사용, 재학습 없음)
python test.py --input <CSV> --image_root <이미지 폴더> --output final.csv

# 가중치를 처음부터 다시 만들 때 (Train + Validation, 약 2~3분)
python train.py --data_dir <battery_data_light 폴더>

# Train만 학습해 Validation 점수 확인 (가중치는 저장하지 않음)
python train.py --data_dir <battery_data_light 폴더> --validate
```

`--image_root`는 이미지가 들어 있는 폴더(`.../test/images`)와 그 위 폴더(`.../test`) 둘 다 받는다.

| 파일 | 내용 |
|---|---|
| `model.py` | 입력 106개 계산(센서 파생변수, 이미지 밝기 통계), LightGBM 학습·예측, 누적 최댓값. 학습과 예측이 같은 함수를 쓴다 |
| `train.py` | Train + Validation으로 학습해 `weights/lgbm106.joblib` 저장. Test는 읽지 않는다 |
| `test.py` | 저장된 가중치로 예측 CSV 생성 |
| `weights/lgbm106.joblib` | 학습된 LightGBM, 범주 코드표, 입력 열 이름과 순서 |

## 3. 학습·검증 데이터를 나눈 방법

| Split | 행 수 | 실험 수 | 용도 |
|---|---:|---:|---|
| Train | 33,522 | 78 | 학습 |
| Validation | 10,200 | 19 | 구성 선택 때는 검증, 최종 가중치는 학습에 포함 |
| Test | 3,451 | 11 | 예측만. 학습, 전처리, 구성 선택에 쓰지 않는다 |

- 구성 선택: Train 78개 실험으로만 학습하고 공식 Validation 19개 실험으로 평가했다. Validation을 원본(5초)과 2행·3행마다 솎은 10초·15초 간격으로 만들어 세 Macro F1을 평균했다.
- 보조 평가: Train + Validation 97개 실험을 **실험 단위** 5-fold로 나눠 2가지 fold 구성으로 10번 평가했다(같은 실험의 행이 학습과 평가에 함께 들어가지 않는다).
- 최종 가중치: 구성을 정한 뒤 Train + Validation 97개 실험 전체로 다시 학습했다.
- 간격 증강: Test에 10초·15초 간격 실험이 있어, 학습 실험마다 2행 중 1행, 3행 중 1행만 남긴 복사본을 더했다. 복사본은 별개 실험으로 취급하고 솎은 뒤에 파생변수를 다시 계산한다.

## 4. 모델 입력 106개

`relative_time_s`는 정렬과 변화율·경과 시간 계산에만 쓰고 모델 입력에는 넣지 않는다.

| 묶음 | 개수 | 내용 |
|---|---:|---|
| 원본 | 17 | 전압, 온도 3종(`meas_t1`, `meas_t2`, `thermal_t`), 압력, 가스 6종(CO, CO₂, CH₄, HF, HCl, SO₂), 주위·히터 온도, 배터리 조건(`bat_class`, `bat_cc`, `soc_status`, `tr_method`) |
| 시계열 파생 | 50 | 이벤트 11(전압 10% 하락, 가스 +5 ppm, HF +1 ppm, 자가발열의 발생 여부와 경과 초), 누적 최댓값 10, 30초 변화율 11, 120초 변화율 5, 정점 이후 6, 상대값 7 |
| 이미지 밝기 통계 | 6 | 열화상 PNG를 흑백으로 바꿔 평균, 표준편차, 최댓값, 95·99 백분위수, 밝기 0.8 이상 픽셀 비율 |
| 규칙 신호 | 33 | 전압 1/6 하락(3→4단계) 4, 표면 온도 45℃ 돌파(1→2단계) 4, 급가열(60초 동안 초당 1℃ 초과) 4, 온도 5종의 정점 대비 하락·비율·경과 초 21 |

### 시계열 피처를 계산한 방법

1. **실험별로 따로 계산한다.** 같은 `experiment_id`의 행끼리만 묶는다.
2. **시간순으로 정렬해 계산하고 원래 행 순서로 되돌린다.** 정렬 키는 `experiment_id`, `relative_time_s`, `sample_id`다.
3. **현재와 과거 관측만 쓴다.** 누적 최댓값·최솟값, 첫 관측값, "조건을 처음 만족한 뒤 경과 초", "t − w초 이후 가장 오래된 과거 행과의 변화율"만 쓴다. 실험 전체의 길이·평균·최댓값, 이후 시점의 값, 다른 실험의 값은 쓰지 않는다.
4. **시간은 초 단위다.** 변화율과 경과 시간은 행 수가 아니라 `relative_time_s` 차이로 계산해 5·10·15초 간격에서 같은 뜻을 갖는다.
5. **결측은 채우지 않는다.** 숫자로 바꿀 수 없는 값과 무한대는 NaN으로 두고 LightGBM이 직접 처리한다. 표준화 같은 전처리 통계는 쓰지 않는다.

그래서 행 순서를 섞거나, 실험을 나눠 넣거나, 각 실험의 뒤쪽 행을 빼도 남은 행의 예측이 같다.

## 5. 모델과 후처리

| 항목 | 설정 |
|---|---|
| 모델 | `lightgbm.LGBMClassifier` 1개 |
| 나무 수 / 학습률 / 잎 수 | 300 / 0.05 / 31 |
| 나무마다 쓰는 변수·행 비율 | 50% / 80% (`colsample_bytree=0.5`, `subsample=0.8`, `subsample_freq=1`) |
| 잎 최소 행 수 | 30 |
| 클래스 불균형 | `class_weight='balanced'` |
| 범주형 변수 | 숫자 그대로 입력 |
| 시드 / 스레드 | `random_state=42`, `n_jobs=8` |

후처리는 확률이 가장 큰 단계를 고른 뒤 같은 실험 안에서 시간순 누적 최댓값을 적용한다(단계는 되돌아가지 않는다). 각 시점은 그 시점까지의 예측만 쓴다.

## 6. 성능

| 평가 | Macro F1 |
|---|---:|
| Validation (Train만 학습, 5·10·15초 평균) | 0.9078 |
| 실험 단위 교차검증 10번 평균 | 0.9111 |
| Public 리더보드 | 0.8946 |

Validation 단계별 F1(세 간격 평균)은 1단계 1.000, 2단계 0.848, 3단계 0.946, 4단계 0.822, 5단계 0.916, 6단계 0.916이다. 남은 오답의 대부분은 2↔3단계 경계다.

### 시도했지만 넣지 않은 것

| 시도 | 결과 |
|---|---|
| ResNet18 임베딩(PCA 8 + 30초 변화량 8)을 입력에 추가 | Validation +0.0017, Public 0.8746(−0.0200) |
| 이미지 CNN·GRU 확률과 가중 평균 | Validation +0.0002 ~ +0.0003 |
| 작은 MLP(64→32) 확률과 가중 평균 | 교차검증 −0.0006(MLP 20%), 채택 기준 미달 |
| 경계 전용 분류기, 전환 투표, 좁은 4→5 규칙 | 교차검증에서 이득이 없거나 하락 |
| 단계별·전환 근처 가중치 조정, 추가 파생변수 71개 | 평가마다 부호가 바뀌는 ±0.01 범위 |

## 7. 사전학습 모델과 규정

- **사전학습 모델: 사용하지 않음.** 이미지는 밝기 통계 6개로만 쓴다.
- **이미지와 센서 모두 사용**: 센서 100개와 이미지 밝기 통계 6개가 같은 모델의 입력이다.
- **현재·과거 행만 사용**: 모든 파생변수와 누적 최댓값이 시간순 누적 계산이다.
- **Test로 학습하지 않음**: 범주 코드표와 모델은 Train + Validation으로만 만들고 저장한다. `test.py`는 저장된 것을 불러와 예측만 한다.
